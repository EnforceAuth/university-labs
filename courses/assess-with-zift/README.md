# Lab: Complete the Extracted Policy

Zift scanned a document service, found authorization embedded in the
application code, and ran `zift extract` to turn those checks into Rego. This
lab is that extracted policy, with the two decision rules removed so you author
them yourself. You validate your work with real `opa` (Zift is a separate Rust
tool and is not run here).

## Files

- `policy.rego` — the starter. It ships the default-deny base
  (`default allow := false`) and the extracted `role_permissions` table. The
  two `allow` decision rules are stubbed out as a `TODO(learner)` block for you
  to implement.
- `policy_test.rego` — the graded test suite: four allow cases and four deny
  cases. **Do not edit this file**; it is the spec your policy must satisfy.

## The exercise

Open `policy.rego` and implement the two `allow` paths described in the
`TODO(learner)` block so all eight tests pass:

1. **Role-based path.** Allow when the requested action is in the set of
   actions permitted for the subject's role. Look the role up in
   `role_permissions[input.subject.role]` and test `input.action` against that
   set with the `in` operator. An unknown role leaves the lookup undefined, so
   `allow` stays false, that is default-deny doing its job.
2. **Ownership path.** Allow a `read` or `write` (never `delete`) when the
   subject owns the resource, i.e. `input.resource.owner_id == input.subject.id`.
   Delete stays role-gated on purpose: owning a document does not let you delete
   it.

Write these as two incremental `allow if` rules. Rego OR-s multiple rules with
the same name together, so a request is allowed if either path holds.

## Run

From the cloned `university-labs` repo:

```bash
git clone https://github.com/EnforceAuth/university-labs.git
cd university-labs
opa test courses/assess-with-zift -v
```

Starter state: `PASS: 4/8` (the four allow tests fail because nothing grants
yet). Target: `PASS: 8/8`.

## What the tests check

The suite encodes the intent of the three original embedded checks:

1. A `requireRole(...)` middleware gating write and delete.
2. An inline `if user.role == "admin"` check on delete.
3. An ownership guard `if doc.owner_id == user.id` on read and write.

The four allow tests confirm each grant works (admin deletes, editor writes,
viewer reads, owner writes their own doc). The four deny tests catch a false
allow, an access the policy grants when it should not: a viewer writing
someone else's doc, an editor deleting, an owner deleting their own doc
(ownership grants read/write only), and an unknown role getting anything. If
you widen the ownership path to cover `delete`, `test_owner_cannot_delete_own_doc`
turns red and tells you.

Keep iterating until `opa test` is green. Certification is graded against a
**hidden** test suite, not this one, so treat this lab as practice, not the
answer key.
